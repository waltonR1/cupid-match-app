# 项目背景说明

## 文档作用

本文档回答三个问题：

- 为什么做这个项目
- 项目解决什么现实问题
- 产品判断依据是什么

全局结构、页面范围和技术链路见 [project-map.md](./project-map.md)。

## 项目背景

`cupid-match` 不是一个以高频互动为目标的泛社交产品，而是一个面向长期关系与真实相亲流程的婚恋平台前台原型。

项目关注的不是“让用户停留更久”，而是“让关系判断更真实、推进路径更清晰”。它更接近现实中的婚恋决策过程，而不是强调持续聊天和轻量互动的线上匹配产品。

## 现实问题

常见婚恋产品普遍存在以下问题：

- 线上资料和聊天内容很难代表真实匹配度
- 用户行为容易停留在浏览、点赞或聊天，缺少明确的推进机制
- 家庭在真实相亲流程中常常主导前期筛选与判断，但产品通常只为个人用户设计

这些问题意味着，很多产品提供的是“认识人”的入口，而不是“建立关系”的完整路径。

## 核心问题

### 线上判断失真

资料、图片和短期聊天不足以支撑真实判断，结果通常是：

- 早期筛选效率低
- 用户投入时间后才发现不匹配
- 关系推进停留在信息层

项目因此把“真实接触”视为结构化链路的一部分。

### 家庭主导推进缺位

在现实相亲里，家庭经常参与前期筛选、判断与推进。项目将家庭视角视为独立路径，而不是个人账户的附属功能。

### 缺少推进路径

很多产品解决的是“如何发现人”，项目解决的是“如何从发现走向接触，再走向发展”。

## 产品理念

### 长期关系导向

平台强调长期关系与真实匹配，不以即时反馈和轻量互动为目标。

### 结构化推进

平台把婚恋过程组织为更清晰的链路：

- 先筛选
- 再判断
- 再接触
- 再发展

### 贴近现实相亲逻辑

平台正面处理以下现实要素：

- 家庭前期介入
- 条件与背景判断
- 线下活动作为接触节点

## 关键判断

### 家庭不是附属角色

家庭用户是一条独立且可主导推进的路径。产品设计不仅服务于个人浏览资料，也服务于家庭在授权边界内进行前期筛选与判断。

### 线下活动不是补充模块

活动承担的是线上筛选与真实接触之间的桥梁角色。没有线下接触节点，平台很容易退回到“资料浏览 + 聊天停留”的旧逻辑。
